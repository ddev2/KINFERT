# KinFert: changes applied on 26 August 2026

Tier A of the pre-release audit: the mechanical fixes, the ones where the correct code
is determined by the surrounding code rather than by a modelling decision. Every site
carries a `// --- CLAUDE 2026-08-26 [ID] begin ... end` block with the replaced code
commented out line by line, so `grep -n "CLAUDE 2026-08-26" *.pas` lists them all.

Line numbers are as committed in `13e7a70` and will move with the next edit. `git diff
290b924..13e7a70` shows the whole set.

## Not applied, and why

**N8, applied and then reverted.** The sterility floor in `Fertility.pas`. The `else` arm
conflates "already sterile at `kMinAgeFert`" with "still fecund at `kMaxAgeFert`" and
assigns `kMinAgeFert` to both, so about 2.8 per cent of women, drawn from the most fecund
tail, are given zero exposure and zero children. The fix is to keep whichever boundary the
loop reached. It changes fertility results, so it belongs with the decisions awaiting you.

**N19, considered and not applied.** The shifted education table mapping in the cohort dump
in `DemographicRegime.pas`. The header writer and the value writer agree with each other,
so the file is self-describing and reads back correctly; what is wrong is that the mode in
force dumps a different table from the one it uses. Correcting it changes the column set of
the cohort file for all three modes, which is a file format decision.

**Noted in the source, not changed.** `getPartner` guards on the literal 20 while
`kMaxNbUnion` is 30, so unions 21 to 30 are rejected with an error message. The note is
inside the N27 block in `Nuptiality.pas`.

**Deleted.** `mothersInfoList.pas` (N39): no unit header, referenced by nothing including
`kinfert.lpi`, uses a constant defined nowhere in the tree, and both entry points begin
with `exit`. Recoverable from git history. `testThread.pas` is a second candidate: it
declares `unit testThreads` while the file is named `testThread.pas`, and nothing
references it either. Left in place for you to decide.

## How this was checked

FPC 3.2.2 and the Lazarus 3.0 LCL, on Linux, in the session container. `LazMain` and
`LazUtiles` were replaced by small stubs for the check because they reach TAChart, whose
`PropEdits` dependency Ubuntu packages only for design time; `LazGraph` was therefore not
checked either. Every other unit compiles, and the compiler warning list is unchanged from
the baseline taken before these edits. The `.lfm` resource binding can only be checked by
Lazarus itself, so the first thing to do is still to build the project there.
